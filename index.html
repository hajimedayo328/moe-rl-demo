3つのツマミが壊すもの

  • エキスパート数を減らす → 容量不足。エキスパート数 < 仕事の種類だと1つのエキスパートが兼任させられ、どんなに学習しても理論上限（赤点線）に届かない（例: エキスパート2・タスク3 で上限0.67）。
  • タスク数を減らす → 分業が不要。optimalArm(ctx)=ctx % タスク数。タスク1なら全 context の正解が同じ arm。1人で足り、特化は起きない／無意味。
  • 報酬ノイズを上げる → 信号の破壊。確率 noise で報酬を反転。ルーターが正解を読めず、特化が収束しない・崩れる。50%で信号は消える。

※ エキスパート数・タスク数は構造が変わるので自動リセット。報酬ノイズは走行中でも反映。

見るべきねじれ：特化度は高いのに報酬が低い

容量不足（エキスパート2・タスク3）にすると、ルーターは各 context をきれいに振り分ける（特化度は高い）のに、箱が足りず報酬は0.67で頭打ち。「分業の構造ができること」と「性能が出ること」は別物——これが容量限界の正体。逆にタスク数1にすると報酬は1.0なのに特化度は低い（分業の必要がない）。両側から「特化≠性能」が見える。

問い ①　実データで答える

崩壊は「離散的な相転移」か「連続的な劣化」か

ノイズを上げると特化はある閾値で一気に壊れるのか、滑らかに溶けるのか。「離散 vs 連続」で言うとどちら側か。
叩き台の持論：「両方」。指標によって崩れ方が違う。 性能（報酬）は連続的に劣化するが、内部構造（特化度）は閾値を超えると相転移的に急落する。 同じノイズという1つのツマミでも、「外から見た性能」と「中の分業構造」は別の壊れ方をする——という主張。下のボタンで実際にスキャンして確かめられる。

各ノイズ値で MoE(エキスパート3・タスク3) をゼロから学習し、収束後の報酬と特化度を測る（各点3試行平均）。 赤い縦線＝特化度が最も急に落ちる位置＝相転移の閾値。

文献上の現在地：「性能(外部指標)は連続／構造(内部指標)は離散」は既出の論争——Schaefferの「相転移は指標の錯覚」に対し developmental interpretability[2508.15841] が「内部の連続診断で不連続を検出」と反論、grokking も一次相転移[2606.17120]として既出。自分の差分＝MoE×RL の最小トイで報酬(性能)と特化度(構造)の乖離を1つの系で操作的に出せること。閾値46%等はトイ固有でスケール則ではない。
問い ②　圏論で見立てる（要検証・先行研究あり）

ハルシネーションは1種類ではない —— 圏論で2つの型に割る

「正しい専門家に振り分けられない」を圏論で。ただし先行研究(TEE[2601.04416]・Misrouted[2605.07260])が既に「容量制限 vs 配分失敗」を分離済み。本研究の差分は2型を圏論で形式化し、RL最小モデルで"天井の上下"として操作的に出し分けること。
coverage型：射が作れない
routing型：射はあるのに選び損なう
叩き台の持論：ハルシネーションは圏論的に異なる2つの失敗。 coverage型＝エキスパートという中間対象が足りない。C0とC2が同じE0に潰れ割り当てが単射でない→正しいarmに分離できず、正しい射がそもそも作れない（構造的）。デモでは天井が下がる（実測: 上限0.67・特化度0.95）。
routing型＝正しいエキスパートは存在する（各ctxに担当Eがある）のにルーターが誤った射を選ぶ。正しい射 C0→E0→A0 が図式に存在するのに別の射 C0→E1→A1 が選ばれる（選択的）。デモでは天井1.0のまま実測だけ落ちる（実測: 報酬0.50・特化度1.0＝能力は満点）。
つまり coverage型＝射が作れない／routing型＝射はあるのに選び損なう。これがMisrouted[2605.07260]の「容量制限 vs 配分失敗」の圏論的な対応物。
引用上の立ち位置：「2型が別物」自体は既出（TEE[2601.04416]が概念分離、Misrouted[2605.07260]が実LLMで実証）。本研究の差分は 単射性の破れ(coverage)／射選択の失敗(routing) という圏論的特徴づけ と トイで"天井の上下"が2型を峻別する実証。圏論が新しい予測（2型の境界・容量閾値）を生むかが次の課題。
問い ③　圏論で見立てる（要検証）

特化の創発を「報酬最大化の普遍性」として書けるか

分業が設計でなく報酬最大化から自然に出てくること自体を、universal property として記述できるか。
叩き台の持論：特化＝正解関数 f の「最小の中間対象による因数分解」。 正解 f: context→arm を、ルーター r とエキスパート方策 p の合成 f = p∘r に分解する。 正解 arm が同じ context は1つのエキスパートにまとめてよい（商＝同値類で割る）。 エキスパート数＝正解 arm のユニーク数のとき、この分解は epi-mono 分解（像）に一致：r は全射（商への射）、p は単射的（像→arm）。 報酬最大化は、この「最小の中間を通る因数分解」を勾配で自動的に見つけている——これがある種の普遍性（像の普遍性／余等化子）だ、という見立て。 ①②③が繋がる：容量不足（②）＝「この最小の中間より小さい対象に押し込んで分解が壊れる」、相転移（①）＝「ノイズで因数分解の探索が閾値を境に失敗する」。
文献点検の結果：epi-mono分解と像の普遍性は標準数学で正しい（＝随伴=dagger のような捏造ではない）が、基礎すぎて新規性はゼロ——「特化＝像分解」は既存概念への翻訳どまり。「最適方策＝像分解」は容量ぴったりで成立（手計算）だが一般は要証明。注意：MoE特化の"factorization"は別物が既出（μMoE[2402.12550]＝テンソル分解）。これ単体で新規性は主張できない。
圏論レンズ（モナド と dagger＝ベイズ逆）。確実に正しいのは確率核・Kleisli合成・ベイズ逆(dagger)まで。 ここで使うのは確率モナドのdagger 構造（ベイズ逆、Fritz/Cho-Jacobs のマルコフ圏で確立）。容量不足を情報の非可逆性として見せる。訂正：これは「随伴(F⊣G)」ではない —— ベイズ逆は dagger functor であって随伴とは別物（最初"随伴の足場"と書いたのは誤り。下のcaveat参照）。学習はタブ①と同じモデルを共有。
ビューA　モナド：Kleisli合成（確実に正しい）

君のデモは丸ごと「確率核の合成」で書ける

ルーター R・エキスパート E は確率行列（マルコフ核）。合成 E∘R（＝Kleisli合成＝核の積）が目標核 f に一致すれば正解。ハルシネーション＝合成核が f から離れること。色が濃いほど確率1。
ハルシネーション距離 ‖E∘R − f‖ = —（0で完全一致）
ビューB　dagger 構造：ベイズ逆と可逆性

容量不足 ＝ 情報が戻らない（非可逆）

R のベイズ逆 R†（事後分布 P(c|e)、マルコフ圏の標準概念）で「expert→どの context だったか」を逆算。R†∘R が恒等に近いほど routing は可逆＝情報を保存。容量不足だと潰れて戻らない。

恒等からの距離 ‖R†∘R − I‖ = —。用語の訂正：このベイズ逆 R† は圏論では dagger functor（Fritz/Cho-Jacobs のマルコフ圏の標準構造）であって 随伴(F⊣G) ではない。当初「随伴の足場」と書いたのは誤り。「随伴で容量不足を書く」は別問題で未解決——every monad は Kleisli/EM 随伴から来るので確率モナドの随伴が出発点になり得るが、それと "ベイズ逆(dagger)の可逆性" は別の話。エキスパート数（タブ①）を 2 に落とすと非可逆になるのを見てほしい。
